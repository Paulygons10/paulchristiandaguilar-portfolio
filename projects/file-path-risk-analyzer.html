File-Path Risk Analyzer

A dual-probability AI analyzer that reads nothing but a file path — and predicts two things detection teams desperately want to know early: how likely this detection is to surge (spike into a flood of hits), and how likely it is to be a false positive.

Role
Project owner — model design, prompt workflow, deployment
Status
Deployed on an LLM application platform
Stack
LLM app workflow · risk scoring

The Problem

File paths are one of the earliest signals a detection system sees, and they're surprisingly informative — installation directories, temp folders, user profiles, and naming patterns all hint at whether activity is routine software behavior or something suspicious. Two failure modes cost teams the most: surges (one detection suddenly firing across thousands of endpoints, flooding queues) and false positives (detections that erode customer trust). Both are often predictable from path characteristics alone — if you can quantify it.

The Solution

An LLM-powered analyzer that scores every file path on two independent axes:

  • Surge probability — is this the kind of path (shared system locations, auto-generated names, common software footprints) that tends to explode into high-volume hit patterns?
  • False-positive probability — does this path profile match legitimate software behavior more than malicious placement?

The two scores together let teams triage before the damage: high-surge candidates get volume safeguards, high-FP candidates get a second look before shipping.

Engineering Highlights

  • Built as an LLM-platform workflow — prompt chains, scoring logic, and I/O contracts live on an LLM application platform, making the analyzer easy for non-developers on the team to invoke and for me to iterate on rapidly.
  • Dual-output design — surge and false-positive are deliberately separate probabilities, not one blended "risk" number, because they trigger different operational responses.
  • Path-only input — a deliberate constraint that keeps the tool fast, privacy-light (no file content leaves the boundary), and usable at the earliest point in the detection lifecycle.

What this project demonstrates: framing an operational pain point as a well-posed prediction problem, choosing the right platform for the audience (low-friction LLM apps over custom services), and designing outputs around the decisions people actually make.
