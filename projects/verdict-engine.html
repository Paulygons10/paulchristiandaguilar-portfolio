LLM Malicious-File Verdict Engine

Two production AI services — one for text-based files, one for PDFs — that analyze suspicious files the way a human analyst would: understand what kind of file it is, read it in context, and decide whether it's malicious. Built to augment large-scale threat triage where traditional signature engines fall short.

Role
Core developer — pipeline, evaluation, deployment
Status
In production
Stack
Python · LLM APIs · Cloud CI/CD

The Problem

Security operations receive enormous volumes of "gray" files — scripts, configuration files, logs, documents — that are neither clearly clean nor clearly malicious. Signature-based engines struggle with these because maliciousness often lives in context: a PowerShell one-liner is harmless in an admin runbook and dangerous in a phishing attachment. Human review doesn't scale; every borderline file that reaches an analyst costs minutes.

The Solution

A pipeline that gives an LLM the same context a human analyst would gather — then holds its verdicts to measurable accuracy standards. Files are classified by type, routed to specialized extractors, scrubbed of sensitive data, analyzed with category-specific prompt chains, and scored against tuned thresholds.

Engineering Highlights

Context-aware extraction, not raw dumps

  • A family of specialized extractors — each file category gets tailored signal extraction instead of raw bytes fed to the model.
  • Performance engineering — parallelized extraction keeps large and complex inputs within latency budgets.

Privacy guardrails before every model call

  • Sensitive-data redaction layer strips customer data before content leaves the pipeline — a hard requirement I treated as a first-class subsystem with its own test suite.
  • Optimized so the privacy layer never becomes the bottleneck at production volume.

Verdicts you can measure

  • Built the accuracy benchmarking harness: standard classification metrics, automated threshold tuning, and evaluation runs across recurring labeled datasets.
  • Regression testing per release — every pipeline change re-runs against historical datasets to catch accuracy drift before deployment.
  • Ground-truth hygiene — the harness surfaces likely mislabeled samples for review, keeping evaluation data trustworthy.

Production resilience

  • Rate-limit-aware LLM request management — sustained throughput within provider limits, with graceful degradation under pressure.
  • Error monitoring + notifiers: automated alerts and recurring operational reports.

Companion: serverless alerting system

  • Designed a serverless alerting layer with error-burst detection (alert on abnormal failure clusters, not single blips) and alert-expiry logic to prevent notification fatigue.

Deployment & CI/CD

  • Automated pipeline deploying to containerized and serverless cloud targets, using keyless cloud authentication — no long-lived secrets in CI.
  • Staged promotion flow with pre-deploy validation and dry-run tests before anything reaches production.
  • Test discipline: unit tests with coverage reporting across every pipeline subsystem.

What this project demonstrates: end-to-end ownership of a production LLM system — data engineering, prompt architecture, privacy guardrails, statistical evaluation, cloud deployment, and the operational maturity (alerting, regression testing, staged releases) that separates a demo from a service.
